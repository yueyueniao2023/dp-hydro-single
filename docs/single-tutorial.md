# 单库：从水量平衡到一维DP，再理解历史状态

先运行：

```bash
mvn compile exec:java "-Dexec.mainClass=Main"
```

原来的 `Main`、`DynamicProgramming` 和 Excel 输入继续可用。当前输出为 [CSV](../results/single/dispatch.csv) 和运行时生成的 `results/single/optimal_dispatch_result.xlsx`。不要把根目录历史Excel当成新运行结果。

## 1. 模型与数据

只有一座水库，已知每旬天然来水，决定各旬末水位，使全年总发电量最大。36旬按非闰年实际天数设置，共365天。输入格式见[数据说明](../data/single/README.md)。

水位790～850 m、步长0.5 m；初水位830 m、末水位严格840 m；水位每旬变化≤30 m。沿用现有代码的7、8月汛限842 m，同时限制旬初和旬末。本次没有依据去把汛期改成5～7月，因此明确保留7、8月作为案例设定。

月内极差定义为**同一个月三个旬末水位的最大值减最小值≤30 m**，不含当月第一旬初水位；相邻边界的30 m限制仍单独执行。这一口径与代码和测试一致，若想包含月初，必须同步修改状态初始化及教程。

总下泄188～5000 m³/s；最大发电流量5000 m³/s；装机3600 MW；综合出力系数8.5，等价于固定效率约8.5/9.81（不另乘一次效率）。水头采用平均库水位减总泄流对应的尾水位，不另设水头损失。

## 2. 给定两个水位就能算本期收益

共用实现为 [HydroPhysics.evaluate](../src/main/java/cascade/HydroPhysics.java)。令库容V单位为亿m³、时长d单位为天：

```text
R = I + (V初 - V末) × 10^8 / (d × 86400)      总下泄，m³/s
H = (Z初 + Z末)/2 - 尾水位(R)                 水头，m
Q发电 = min(R, 5000, 3600×1000/(8.5×H))       m³/s，H>0
Q弃水 = R - Q发电
P = 8.5 × Q发电 × H / 1000                    MW
E = P × d × 24                               MWh
```

总下泄不满足边界直接排除，不能把R夹到188或5000后继续算。限制发电流量的同时，超出的水进入弃水，水量仍完整保留。CSV电量为MWh，兼容旧Excel字段时除以10转为万kWh。

## 3. 先理解不含月内极差的一维DP

`F[t][j]` 表示运行t期、到达水位j的最大累计电量。阶段是旬，状态是旬末水位，转移由上一旬末水位i走到本旬末水位j。

```text
F[0][830m] = 0；其他初态 = -∞
F[t+1][j] = max_i { F[t][i] + E(t,i,j) }，只考虑物理可行转移
previous[t+1][j] = 取得更大值的i
最终读取 F[36][840m]，沿previous反向回溯
```

不要用0表示不可达，也不能在840 m附近另挑一个收益高的终点。

## 4. 为什么这里还要记本月最低/最高水位

例如本月第二旬末同为820 m，两条历史路径可能分别为：

- 第一旬末790 m、第二旬末820 m：本月范围[790,820]。
- 第一旬末810 m、第二旬末820 m：本月范围[810,820]。

第三旬末若选830 m，第一条极差40 m不可行，第二条极差20 m可行。即使第一条此前收益更高，也不能只留下它；后续可行性依赖历史。

因此 [DynamicProgramming.State](../src/main/java/DynamicProgramming.java) 使用：

```text
State(当前水位索引, 本月最低旬末水位索引, 本月最高旬末水位索引)
```

每个新月的第一旬，把本月min/max都设为该旬末水位；后续旬转移时扩展min/max并检查极差。月末检查完成后，下一月不再使用旧极值，可以按当前水位安全合并。每个Node保留其真正前驱和物理结果，回溯不会误接别的路径。

代码还把某期所有“初水位→末水位”的物理结果预计算一次。历史状态不同但初末水位相同，物理量完全相同，可以复用；这不删掉任何可行历史。

先预测“把某一期末水位调高，会让本期总下泄增加还是减少”，再用公式验证。一次只改一个参数，始终保持初末状态一致，才能公平比较收益。

## 本次修复了什么

| 旧问题 | 修复及原因 |
| --- | --- |
| 只在已合并路径上沿prev链校验月内极差，且索引链起点不对应候选前驱 | 扩展状态保留历史极值；只有未来约束不再依赖它们时才合并 |
| 36旬都按10天，总计360天 | 水量及电量统一使用实际旬长365天 |
| 末水位允许附近搜索 | 严格840 m，不可达就报错 |
| 尾水表从第5行读起，遗漏第4行有效数据；低流量静默取曲线端点 | 正确读到350 m³/s起的数据；增加独立、明确标为合成的188 m³/s补点；越界报错 |
| 发电与回溯尾水可能分别使用总泄流、发电流量；弃水时直接套满发电量 | 三例共用物理公式，按总泄流查尾水，按真实发电流量及实际旬长计算 |
| 主入口只打印异常，进程可能表现为成功 | 异常传给Maven，运行失败明确返回失败 |
| 原绘图按360天且静默截断基准流量 | 同步时长与发电公式，不可行基准明确拒绝；绘图输出独立目录 |

Excel读取改为一次读取、缓存曲线并自动关闭资源，是为了让扩展状态DP不会在内层循环反复排序。原Excel字节保持不变。历史结果保留，不据此推断新代码的收敛性或提升率。
